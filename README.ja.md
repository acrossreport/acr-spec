# ACR 仕様

**ACR（Across Report）** は、現代のソフトウェアシステムのために設計された、プリンタに依存しない帳票仕様です。

> *Render once. Output everywhere.*

ACRは、レイアウトの記述・描画・出力の生成を分離しています。  
これにより、同じテンプレートを複数のプラットフォームと出力形式で描画できます。

---

## なぜACRか

従来の帳票システムは、特定のプリンタ・描画エンジン・フレームワークと強く結びついています。

ACRは、整理された階層構造を採用しています。

```
テンプレート → レイアウトエンジン → 描画エンジン → 出力
```

各層の役割は1つだけです。

| 層                   | 役割                                                           |
|----------------------|----------------------------------------------------------------|
| **テンプレート**     | JSONによる帳票定義。プラットフォームに依存しない。             |
| **レイアウトエンジン** | セクションの解決、データの結合、位置の計算を行う。            |
| **描画エンジン**     | Google Skiaでピクセルに描画する。1ドット精度。                 |
| **出力**             | PDF、PNG、SVG、その他の出力形式。                              |

この分離により、次のことが実現します。

- 同じテンプレートが、変更なしでWindows・macOS・Linuxで動作する。
- デザイナーのプレビューが、最終的な印刷結果と**ピクセル単位で一致**する（WYSIWYG）。
- 出力形式は制約ではなく、選択肢の1つにすぎない。

---

## 設計の原則

**プリンタ非依存**  
ACRは、プリンタドライバやOSの印刷機能に依存しません。レイアウトはデバイスに依存しない単位で計算し、出力先の解像度で描画します。

**中間モデルとしてのJSON**  
テンプレートは、人が読めるJSONで定義します。レイアウトエンジンが生成する描画モデルもJSONで、描画とは独立して確認・キャッシュ・転送できます。

**Skiaによる描画**  
描画エンジンには、ChromeやAndroidにも使われているグラフィックスライブラリGoogle Skiaを使用しています。これにより、どのプラットフォームでも一貫した高精度の出力を保証します。

**セクション型の帳票モデル**  
ACRは、業務帳票で広く使われているセクション型の構造（レポートヘッダー／ページヘッダー／グループヘッダー／明細／グループフッター／ページフッター／レポートフッター）を採用しています。既存の帳票定義からの移行の手間を最小限に抑えます。

**実機不要のプレビュー**  
プリンタ・ドライバ・専用ハードウェアがなくても、ピクセル単位で正確なプレビューを確認できます。画面で見たとおりに印刷されます。
